## Rules that are easy to break

**Two zooms.** The OS uses `--desk-scale` (see "Responsive" below) on `<html>`, set before paint in `src/app/layout.tsx`. Works and AI Workflow also set CSS `zoom` on their document column via `useFitZoom` (design widths 1872 and 1608). `getBoundingClientRect()` is post-zoom. `scrollTop`, `offsetTop`, and `clientWidth` are pre-zoom. Pointer math must use the measured ratio `getBoundingClientRect().width / clientWidth`. `position: sticky` and `position: fixed` are unreliable inside a zoomed overflow scroller. Pin with JS. In tablet mode a third zoom sits on some windows and home elements (see "Tablet" below); the measured-ratio rule covers it.

**Theme and cursor are separate.** `documentElement.dataset.theme` + `localStorage["xero-theme"]`. Cursor color is `dataset.cursor` + `localStorage["xero-cursor"]`. Changing Appearance does not change the cursor, and the reverse. If no cursor is saved, the boot script copies the theme once.

**Scroll reveal.** Wrap a block in `<Reveal>` inside an element with `reveal-root` (the scroller). Put `data-reveal-zoom` on the node whose `style.zoom` changes. The hook measures with `getBoundingClientRect` against that scroller. Do not switch it to `IntersectionObserver`; zoom makes that report the whole page as visible. The first screen is shown immediately. Everything below stays at opacity 0 until its top crosses the fold, then fades up. Reduced motion shows everything.

## Performance rules

- No CSS `filter: drop-shadow` / `blur()` on anything that moves or sits inside something that moves; use box-shadow and radial gradients.
- Flyouts have no backdrop blur (they are ~90% opaque).
- Scroll handlers go through `useFrameThrottle` (`src/lib/scroll.ts`); scroll-linked writes are batched read-then-write in one rAF.
- Window drag moves by transform and commits geometry on release.
- Do not run `npm run build` while the dev server is running: both write `.next` and the dev server dies.
- **Measure GPU cost with `--disable-gpu`** (software raster + SwiftShader WebGL). On a desktop GPU, rAF frame times stay at the refresh rate even when the GPU is overloaded. Software mode turns GPU work into frame time, which stands in for a laptop iGPU. Also measure on a production build (`next start`), not dev.
- **Live wallpaper** (`LiveWallpaper.tsx`) is the most expensive thing on screen. Its full-res shader redraws at 30 fps, and every redraw makes each backdrop-blurred surface above it re-blur. It holds still while `html[data-motion]` is set and while a maximized window is up (`[data-window][data-maximized]`). Anything new and big that animates should call `holdMotion()` / `holdUntil(transition)` (`src/lib/motion.ts`).
- **Window View Transitions capture only the window**: `html.vt-win` sets `view-transition-name: none` on the root, so the desktop is not snapshotted and stays live underneath. The named window's backdrop blur is off while it is captured (inside a snapshot it samples nothing, so no pixel changes). Theme / language wipes still capture the root; their `::view-transition-group(root)` has `animation: none`, because the UA width/height tween forced a main-thread frame every frame. Colour transitions are frozen during the theme wipe.
- **Maximize / restore morph** (`morphFrame`) cancels the UA group animation and animates `transform` + `clip-path: inset(… round 20px)` on the group (compositor-only; `html.vt-morph` lets the snapshots keep their own size). Do not go back to animating group width/height.
- **Never pair `backdrop-filter: none !important` with `-webkit-backdrop-filter: none !important`**. The production CSS minifier drops the unprefixed one, so the rule does nothing in Chrome. This is why `.win-anim` never actually turned blur off before. Write only the unprefixed declaration; the build adds the prefix.
- **Works' hidden pre-rendered case study** (~4k layout objects) gets `content-visibility: hidden` while motion runs, so maximize/restore does not re-lay it out. Its idle pre-render runs in `startTransition` and waits until no transition is running. `useFitZoom` ignores 0-width measurements.
- Oct 2026 numbers, 1920×1080, software GPU, frame time p50 before → after: About maximize 96 → 42 ms (paints per morph 362 → 38), About restore 75 → 21, minimize 50 → 12.5, theme wipe 21–38 → 21–25 (paints 442 → 43), language 33–46 → 25, Works maximize 33 → 8.4, Works scroll 25 → 8.3 (p95 42 → 8.4), case study open 25 → 4.2, case study scroll 29 → 17, AI Workflow maximize 25 → 4.2. On a desktop GPU at 4× CPU throttle, the main thread was not the bottleneck for these: p95 was 4.3 ms before and after.
